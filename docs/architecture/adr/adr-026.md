# ADR-026: Xác thực AI CLI bằng token thuê bao trong môi trường; bước setup và doctor

**Trạng thái:** Accepted (Product Owner duyệt)
**Ngày:** 2026-08-19

## Bối cảnh

Hướng B gọi AI qua subprocess một AI CLI (ADR-025). CLI cần được xác thực. Ràng buộc chi phí là lý do chọn B, nên cách auth phải giữ được giá thuê bao (không per-token). Bí mật không nằm trong kho mã (BR-220, NFR-201). Mỗi máy phải có CLI + auth trước khi dùng tính năng AI (BR-221); nền tảng cung cấp bước **cài đặt** (FR-ENV-01) và **kiểm tra tình trạng** (FR-ENV-02).

Claude Code có ba cách auth: khóa API (`ANTHROPIC_API_KEY`, per-token), token OAuth thuê bao (`CLAUDE_CODE_OAUTH_TOKEN` từ `claude setup-token`, dài hạn ~1 năm, tính theo thuê bao), và đăng nhập trình duyệt (tương tác). Token thuê bao dùng trong chính CLI thật (`claude -p`) là đường hợp lệ và rẻ; nền tảng chỉ set biến môi trường rồi chạy CLI thật, không phải tự xác thực một SDK bên thứ ba.

Phase 1 đã có cơ chế bí mật toàn cục ngoài kho mã (`.env.local` gốc, git-ignored, che ở tầng log — ADR-009). Hướng B **không** cần `config.db` (ADR-023, cho A) vì không quản danh sách nhà cung cấp/nhiều khóa — chỉ một token cho một CLI.

## Các phương án đã cân nhắc

### Phương án A: Token thuê bao trong file env git-ignored, nền tảng tiêm vào subprocess (chọn)
`make setup` hướng dẫn `claude setup-token` một lần → lưu `CLAUDE_CODE_OAUTH_TOKEN` vào file env git-ignored; khi spawn `claude`, nền tảng tiêm biến này vào môi trường tiến trình con.
- **Ưu điểm:** Giữ giá thuê bao (rẻ) — đúng mục tiêu B. Tái dùng đúng pattern `.env.local` git-ignored + che log của ADR-009, không thêm khái niệm lưu trữ mới. Token là bí mật đơn, hợp file env phẳng (khác danh sách có cấu trúc của A). Nền tảng chỉ chạy CLI thật với token → không vướng lệnh cấm OAuth cho SDK bên thứ ba.
- **Nhược điểm:** Bước `setup-token` là một-lần-tương-tác (không zero-touch). Token gắn thuê bao của người dùng; có rate limit khi dùng nhiều.
- **Tham chiếu:** [Authentication — Claude Code Docs](https://code.claude.com/docs/en/authentication); cơ chế `.env.local` của ADR-009.

### Phương án B: Khóa API `ANTHROPIC_API_KEY` trong env
- **Nhược điểm:** Tính per-token → mất lợi thế chi phí, phá lý do chọn B.

### Phương án C: `config.db` như hướng A (ADR-023)
- **Nhược điểm:** Cấu trúc cho nhiều khóa/nhà cung cấp; B chỉ có một token một CLI — thừa. Không áp dụng.

## Quyết định

Chọn **Phương án A**: token thuê bao (`CLAUDE_CODE_OAUTH_TOKEN`) lưu trong file env git-ignored ở gốc (theo pattern `.env.local` của ADR-009), nền tảng tiêm vào môi trường khi spawn CLI. Nền tảng KHÔNG giữ khóa API, KHÔNG dùng `config.db`.

Cung cấp hai bước lệnh:
- **`make setup`** (FR-ENV-01, UC-205): chọn CLI → kiểm CLI đã cài chưa (`command -v`) → nếu chưa, cài hoặc hướng dẫn cài → hướng dẫn `claude setup-token` một lần → lưu token vào file env git-ignored.
- **`make doctor`** mở rộng (FR-ENV-02): kiểm CLI có mặt và token hợp lệ; thiếu thì báo rõ, tính năng AI không chạy, phần chạy test không dùng AI vẫn hoạt động.

## Hệ quả

- Biến môi trường token (git-ignored) đăng ký che ở tầng log (cơ chế ADR-009); token không vào log/kết quả/báo cáo. `config/secrets.ts` mở rộng đọc token này; khóa `ANTHROPIC_API_KEY` của Phase 1 không còn là đường auth AI của B (nền tảng không tự gọi API).
- `data/config.db` (ADR-023) không được tạo trong hướng B.
- CLI là phụ thuộc môi trường như Xcode/Appium (BR-221); `make doctor` kiểm cùng chỗ với các phụ thuộc host khác (ADR-010/§doctor Phase 1).
- Bước cài CLI trong `make setup` chọn được CLI (chuẩn bị seam đa-CLI của ADR-025), nhưng giai đoạn này chỉ Claude Code.
- Điều kiện xem lại: nếu chính sách token thuê bao đổi, hoặc khi thêm CLI thứ hai cần token riêng — mở rộng lược đồ lưu token theo CLI.
