# ADR-025: Gọi AI qua một AI CLI bên ngoài bằng subprocess (thay ADR-005)

**Trạng thái:** Accepted (Product Owner duyệt)
**Ngày:** 2026-08-19

## Bối cảnh

Product team đổi cách dùng AI (hướng B): nền tảng KHÔNG nhúng AI qua API, mà **chủ động gọi một AI CLI bên ngoài** (giai đoạn này là Claude Code) tại các điểm cần AI — lý do chi phí (dùng lại thuê bao trên máy, không mua khóa API) và trách nhiệm quản khóa/nhà cung cấp chuyển sang chính CLI (`srs.md`/`business-rules.md` Phase 2, BR-219).

Nền tảng chạm AI đúng hai chỗ:
- **Tự phục hồi locator** (lúc chạy): locator hỏng → cần một locator thay thế. CLI chỉ trả **một chuỗi locator**; nền tảng không để CLI sửa file lúc chạy (tiến trình đang chạy không nhận thay đổi file) (BR-219).
- **Sinh test case** (QC chủ động): CLI sinh file nháp (`.feature`, step, Page Object).

Ràng buộc: giữ vai "điểm kiểm soát" của ADR-005 (bật/tắt theo app, giới hạn số lần gọi/lượt chạy, timeout mỗi lần); chi phí thuê bao chỉ hợp lệ khi gọi qua chính CLI thật; spec dựng quanh "cài một AI CLI + token + chọn CLI" (BR-219/220/221, FR-ENV), và chừa chỗ cho một CLI thứ hai (Codex) về sau mà không xây sẵn đa-CLI; posture ít phụ thuộc; nội dung test không dính CLI nào.

## Các phương án đã cân nhắc

### Phương án A: Subprocess `claude -p` (chọn)
Nền tảng spawn CLI ở chế độ không tương tác (`claude -p --output-format json`), đưa prompt qua stdin, nhận JSON ở stdout, parse trường `result` và kiểm bằng Zod. Đặt sau một port nội bộ `CodeAgent`; mỗi CLI một adapter (giai đoạn này chỉ Claude Code).
- **Ưu điểm:** Gọi *chính Claude Code thật* → dùng thuê bao qua token là đường hợp lệ và rẻ (credit automation của thuê bao bao gồm lệnh `claude -p`). Khớp mô hình "cài + chọn CLI + token" của spec; Codex cũng subprocess-được nên seam `CodeAgent` thật sự CLI-agnostic. Không nhúng SDK AI vào nền tảng — phụ thuộc là binary người dùng cài (posture ít phụ thuộc). `--allowedTools`/`--permission-mode` cho phép giới hạn quyền theo từng việc.
- **Nhược điểm:** Phụ thuộc một binary ngoài phải cài + auth trên máy (ADR-026). Đầu ra là văn bản/JSON phải parse, không có kiểu tĩnh sẵn.
- **Tham chiếu:** [Run Claude Code programmatically — headless](https://code.claude.com/docs/en/headless); [Authentication — Claude Code Docs](https://code.claude.com/docs/en/authentication).

### Phương án B: Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`, TS)
Điều khiển agent runtime của Claude Code bằng code TS, `query()` một-phát.
- **Nhược điểm:** Nhúng SDK vào nền tảng = một "third-party tool"; Anthropic đã siết chính sách cấm OAuth thuê bao ngoài Claude Code/Claude.ai → rủi ro rớt về khóa API tính-per-token, **mất lợi thế chi phí** — lý do chính chọn hướng B. Thư viện Anthropic-riêng → **khóa cứng vào Anthropic**, phá seam đa-CLI (Codex không dùng SDK này).
- **Tham chiếu:** [Anthropic bans subscription OAuth for third-party use (2026)](https://alternativeto.net/news/2026/2/anthropic-officially-bans-using-subscription-authentication-for-third-party-claude-use).

### Phương án C: Nền tảng nhúng AI qua API nội bộ (hướng A, ADR-005/022)
Lớp AI Client + adapter nhà cung cấp trong nền tảng.
- **Nhược điểm:** Nền tảng ôm khóa API + quản nhà cung cấp + chi phí per-token — đúng thứ product team bỏ khi chọn B.

## Quyết định

Chọn **Phương án A**: nền tảng gọi AI bằng **subprocess một AI CLI bên ngoài** (`claude -p --output-format json`), đặt sau một port nội bộ **`CodeAgent`** (một adapter mỗi CLI; giai đoạn này chỉ Claude Code). Thay ADR-005.

Port `CodeAgent` là điểm kiểm soát duy nhất: bật/tắt AI theo app, giới hạn số lần gọi/lượt chạy, timeout mỗi lần gọi, và là nơi duy nhất dữ liệu (page source) rời máy. Hai chế độ gọi:
- **Heal (read-only):** prompt yêu cầu *chỉ trả một locator*; `--allowedTools` rỗng/chỉ đọc; parse `result` → Zod ra `Locator`. Không sửa file.
- **Generate:** prompt yêu cầu sinh file nháp; quyền ghi giới hạn theo cấu hình.

Bác Phương án B vì khóa cứng Anthropic + rủi ro billing per-token phá lợi thế chi phí. Bác Phương án C vì là hướng A đã bỏ.

## Hệ quả

- Module `ai/` định nghĩa lại cho hướng B: port `CodeAgent`, adapter `claude-code`, prompt tách khỏi mã gọi, và hai nơi dùng (heal, generate). Chi tiết ở `component-design.md` Phase 2.
- Chế độ **generate** được **ADR-028** (Accepted 2026-08-22) tinh chỉnh thành **phiên agent có công cụ Appium MCP** (AI tự lái thiết bị khám phá lấy locator), thay mô hình page source tĩnh + `invoke` một-lần; chế độ **heal** giữ `invoke` một-lần. ADR-025 không bị Superseded (heal + seam còn đúng).
- ADR-005 (Claude Client API) được thay; ADR-021/022/023 (giao diện cấu hình AI, AI Client đa nhà cung cấp nội bộ, config.db khóa — đều cho hướng A) không áp dụng theo pivot B.
- Locator Resolver (điểm chèn heal, ADR-004) gọi `CodeAgent` thay vì AI Client; nhận **chuỗi locator**, thử live in-memory (ADR-004/024).
- Nền tảng **không tạo pull request, không đụng git** (quyết định PO 2026-08-19): con người áp locator + mở PR sau review. Không tích hợp git/gh trong `src/`.
- CLI phải được cài + auth token trên máy (ADR-026); thiếu thì tính năng AI không chạy, phần chạy test không dùng AI vẫn hoạt động (BR-221).
- Guardrail đa hệ điều hành: `CodeAgent` chỉ page-source-vào/locator-ra; đặc thù iOS giữ ở module `locator`. Phase 3 (Android) không đụng lớp AI.
- Đầu ra CLI parse qua `--output-format json` + Zod (dữ liệu ngoài phải qua schema). Prompt heal ràng buộc CLI trả đúng một locator.
- Điều kiện xem lại: thêm adapter CLI thứ hai (Codex) khi có nhu cầu; xét lại nếu chính sách auth/billing của CLI đổi, hoặc nếu Agent SDK cho phép thuê bao ổn định về sau.
